## Source and generated areas

| Area | Location | Role |
| --- | --- | --- |
| Page generation | `scripts/build-store.js` | Builds the root, Guest, Customer Storefront, six Member Profile routes, Creator Dashboard, author, and store page HTML from templates and repository data. |
| Pages artifact preparation | `scripts/build-pages-output.mjs` | Copies an allowlist of public root files and directories into `.wrangler/*-pages-output`; it requires the `functions/` source tree and excludes local-only files. |
| Pages Functions | `functions/` | Runtime API and request handlers deployed with the static Pages artifact. `_routes.json` limits which paths are sent through Functions. |
| Shared and role-specific styles | `styles.css`, `assets/css/` | Shared site/storefront presentation and narrowly scoped page styles. |
| Browser code | `assets/js/` | Storefront rendering, shelf data hydration, account/session behavior, navigation, and other client behavior. |
| Public source data and assets | `data/`, `assets/`, `media/`, `shared/` | Build inputs, public static resources, and shared runtime modules. Product files and object storage have additional ownership rules in the relevant catalog documentation. |
| Project records | `docs/` | Operational, architecture, continuity, and feature-specific records. |

The build output is not a `public/` directory. `scripts/build-pages-output.mjs` defaults to `.wrangler/production-pages-output`; deployment configs select their respective output directories.

## Public page routes

| Route | Source/output mapping | Notes |
| --- | --- | --- |
| `/` | `_redirects` rewrites to `/guest/`; generated root `index.html` is also present in the artifact. | The explicit rewrite is `/ /guest/ 200`. The Guest page is the canonical storefront visual source. |

| `/premium-creator-profile/` | `premium-creator-profile/index.html`, generated by `renderMemberProfilePage()`. | Premium Creator route into the common Member Profile Base. |

| `/owner-profile/` | `owner-profile/index.html`, generated by `renderMemberProfilePage()`. | Owner route into the common Member Profile Base. |

The six Profile HTML files are temporary entry points generated by one renderer. Keep all six files and routes until the dynamically generated member-specific Profile system has passed functional and visual acceptance; no route is retired by this plan. A path does not grant a role or privilege: `/api/account/me` derives the displayed identity and account class from the authenticated session and existing D1 records. Customer Storefront `/customer` and Creator Dashboard `/creator-dashboard/` remain separate pages. Approved member navigation, Profile, Dashboard, and purchase-library ownership decisions are specified in [Member Account Architecture](MEMBER-ACCOUNT-ARCHITECTURE.md); this reference does not imply those behaviors are implemented.
