## Source and generated areas

| Area | Location | Role |
| --- | --- | --- |
| Page generation | `scripts/build-store.js` | Builds the root, Guest, Customer, Creator, author, and store page HTML from templates and repository data. |
| Pages artifact preparation | `scripts/build-pages-output.mjs` | Copies an allowlist of public root files and directories into `.wrangler/*-pages-output`; it requires the `functions/` source tree and excludes local-only files. |
| Pages Functions | `functions/` | Runtime API and request handlers deployed with the static Pages artifact. `_routes.json` limits which paths are sent through Functions. |
| Shared and role-specific styles | `styles.css`, `assets/css/` | Shared site/storefront presentation and narrowly scoped page styles. |
| Browser code | `assets/js/` | Storefront rendering, shelf data hydration, account/session behavior, navigation, and other client behavior. |
| Public source data and assets | `data/`, `assets/`, `media/`, `shared/` | Build inputs, public static resources, and shared runtime modules. Product files and object storage have additional ownership rules in the relevant catalog documentation. |
| Project records | `docs/` | Operational, architecture, continuity, and feature-specific records. |

The build output is not a `public/` directory. `scripts/build-pages-output.mjs` defaults to `.wrangler/production-pages-output`; deployment configs select their respective output directories.

## Public page routes

| Route | Source/output mapping | Notes |
| --- | --- | --- |
| `/` | `_redirects` rewrites to `/guest/`; generated root `index.html` is also present in the artifact. | The explicit rewrite is `/ /guest/ 200`. The Guest page is the canonical storefront visual source. |
| `/guest/` | `guest/index.html`, generated by `scripts/build-store.js` from the Guest storefront builder. | Public Guest storefront. |
| `/customer` | `customer.html`, generated from the rendered Guest page by `renderCustomerLandingPage()`. | Cloudflare Pages serves the static HTML page at its extensionless route. |
| `/creator/` | `creator/index.html`, generated from the rendered Guest page by `renderCreatorIdentityPage()`. | Canonical Creator Profile/Dashboard furniture surface with role-specific identity/session behavior. |
| `/authors/` and `/authors/<slug>/` | `authors.html` and generated `authors/<slug>/index.html`. | Public author profiles; distinct from `/creator/`. |
| `/store/` and `/store/open-rules-library/` | Generated under `store/` by `scripts/build-store.js`. | Static store/catalog pages coexist with runtime APIs. |
| `/creator-dashboard/` | `creator-dashboard/index.html`, using `renderCreatorFurniture()` from `scripts/build-store.js`. | Permanent private Creator Dashboard with the same shared furniture as `/creator/`. |

`_routes.json` includes `/creator/*`, `/customer.html`, `/store/*`, and the listed API route families for Pages Functions. It does not route every static page through a Function.

## Cloudflare deployment configuration locations

- Staging Pages project: `ops/staging/wrangler.pages.toml`; its artifact directory is `.wrangler/staging-pages-output`.
- Acceptance Pages project: `ops/acceptance/wrangler.pages.toml`; its artifact directory is `.wrangler/acceptance-pages-output`.
- Production Pages project: `ops/production/wrangler.pages.toml`; its artifact directory is `.wrangler/production-pages-output`.
- The repository root also contains `wrangler.toml`. Environment-specific deployment work must use the explicitly appropriate configuration and preserve its bindings; do not replace the root file by assumption.

This record identifies source and configuration locations. It does not assert which deployment is currently live or authorize a deployment.
