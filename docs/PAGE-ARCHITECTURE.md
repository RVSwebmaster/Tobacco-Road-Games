# TRG page architecture

Last verified: 2026-11-19 against `scripts/build-store.js`, `scripts/build-pages-output.mjs`, `_redirects`, and `_routes.json`.

## Storefront composition

Guest is the canonical storefront composition. `scripts/build-store.js` produces the Guest page and uses its rendered result as the input for the role variants:

- `renderGuestLandingShopWallMain()` assembles the Guest main area.
- `renderStorefrontUpperCabinet()` owns the shared upper cabinet frame and frozen responsive cabinet artwork.
- `renderGuestLibraryBay()`, `renderGuestOpenRulesBay()` / `renderRoleOpenRulesBay()`, `renderHomepageIdentityBay()`, and `renderHomepageShelfFixtures()` provide the corresponding shared or role-configured markup.
- `renderCustomerLandingPage(guestLandingPage)` derives Customer from Guest and adds Customer-specific session, navigation, and library hooks.
- `renderMemberProfilePage(guestLandingPage, options)` is the canonical Member Profile Base renderer. It composes the approved Creator furniture from shared cabinet parts and generates the Customer, Creator, Founding-25, Premium Creator, Admin, and Owner Profile routes. Only the Creator route receives the Creator catalog-rotation script.

The frozen shared cabinet assets are `assets/images/storefront-shelf-dressing/upper-cabinet-desktop.png`, `upper-cabinet-tablet.png`, and `upper-cabinet-mobile.png`. Guest and Customer Storefront continue to use these unchanged. The six Member Profiles share the approved Creator-scoped desktop, tablet, and mobile title-board variants and the same rendered frame, shelves, identity board, emblem, lighting, and framed display. Their common presentation lives in `assets/css/member-profile.css`; `assets/css/creator-dashboard.css` imports this canonical stylesheet for the separate existing Dashboard. Furniture geometry remains in shared renderers and CSS, never in six role-specific page copies.

## Approved public navigation

- **Verified 2026-11-18:** The public primary navigation contains exactly Explore (`/store/catalog/`), Support (`/support.html`), Login/Signup (`/account.html`), and Cart (`/store/cart/`). `PUBLIC_NAV_ITEMS` in `scripts/build-store.js` is the shared source for Guest and homepage navigation; the root, Support, and Account pages contain the same four links.

## Runtime responsibilities

- Shared storefront book and shelf behavior is loaded through the generated page scripts in `assets/js/`, including `storefront.js`, `open-rules-library.js`, and `homepage-shelves.js` where included by the page.
- Customer account/session and ownership behavior remains Customer-specific and is connected to the account APIs under `functions/api/account/`.
- The member identity board is shared by all Profiles in `assets/js/member-identity-board.js`. `/api/account/me` supplies session-authenticated public `displayName`/`avatarUrl` from `TRG_ORDERS.user_account_profiles` and the account class derived from the authenticated role, Creator memberships, Founding-25 assignment, or active Premium Creator tier. Unauthenticated sessions render an empty identity space. The authenticated account library API returns purchased products, but no persistent member shelf-selection implementation was found. The Profile library therefore leaves shelves empty rather than choosing arbitrary purchases or assuming a shelf capacity; persistent personal shelf selection and population are unfinished. The library session watcher clears existing shelf content when the authenticated member changes. Creator publishing remains in Dashboard APIs and `assets/js/creator-dashboard.js`; membership and eligibility checks remain authoritative in those existing handlers.
- Public shelf/catalog APIs are Pages Functions, including `functions/api/homepage-shelves.js` and `functions/api/catalog.js`. Their response and selection rules are owned by those handlers and supporting `_lib` modules; static HTML generation is not a substitute for their runtime data contract.
- `/authors/<slug>/` is a public author profile generated by the author-page functions. It is not the private/identity-oriented `/creator/` page.

## Page ownership and change boundaries

| Page | Shared source | Page-specific responsibility |
| --- | --- | --- |
| Guest (`/guest/`, and root rewrite) | Canonical storefront generator, shared cabinet, common styles and shelf renderer | Guest navigation and public browsing behavior. |
| Customer Storefront (`/customer`) | `renderCustomerLandingPage()` and Guest storefront furniture | Customer browsing and storefront behavior. It is not the Customer Profile. |
| Customer, Creator, Founding-25, Premium Creator, Admin, Owner Profiles | `renderMemberProfilePage()` / Member Profile Base | Account-specific identity and class come from the signed-in account API; all six use the same profile markup, stylesheets, identity board, personal-library shelves, and framed display. Creator cover rotation is scoped to `/creator/`. |
| Creator Dashboard (`/creator-dashboard/`) | Existing Dashboard template and Creator Dashboard runtime, with shared furniture components | Private publishing and account operations. It remains a distinct Dashboard surface and retains its route and controls. |
| Public author profile (`/authors/<slug>/`) | Author profile generators and common site shell | Public-facing author content; independent of the Creator identity page. |
